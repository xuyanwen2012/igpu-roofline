01

Read 8 × 16 × 16 as M × N × K

A shape describes one small matrix operation. The first two numbers give the output’s size; the third tells you how many products are summed for each output element.

M · output height8 rows

How many rows the result has.

N · output width16 columns

How many columns the result has.

K · reduction length16 products

How many pairs are multiplied and summed for each result element.

A8×16 × B16×16 + C8×16 = D8×16

A · left input8 rows, each containing 16 values.

B · right input16 columns, each containing 16 values.

C · sum so farOne existing value per output element.

D · updated resultThe product plus the existing values.

Follow one output element

Take the first row of A and the first column of B. Multiply their matching values and sum the 16 products. Then add C[0,0].

D[0,0] = A[0,0]·B[0,0] + … + A[0,15]·B[15,0] + C[0,0]

If all 16 input pairs are 1×1, their sum is 16. With C[0,0] = 0, the result is 16. With C[0,0] = 10, the result is 26. The same rule applies independently at every output position.

Why is there a C?

C holds what you have already accumulated. For a standalone multiplication, set every element of C to zero. For a larger multiplication, calculate the result in pieces and use the previous D as the next C.

For example, multiply an 8×48 matrix by a 48×16 matrix. Split the shared dimension, 48, into three chunks of 16. Each chunk uses the same 8×16×16 shape and contributes to the same 8×16 output.

1 · first 16 productsD₁ = A₁B₁ + 0

Start with a zero C.
Example element: 16 + 0 = 16

2 · next 16 productsD₂ = A₂B₂ + D₁

Previous result D₁ becomes C.
Example element: 32 + 16 = 48

3 · final 16 productsD₃ = A₃B₃ + D₂

Previous result D₂ becomes C.
Example element: 48 + 48 = 96

Numerical example: B contains ones; A contains ones in its first 16 columns, twos in the next 16, and threes in the final 16. Each output element is therefore 16×1 + 16×2 + 16×3 = 96. Every intermediate result remains 8×16.

What does “FP16 → FP32” mean?

A and B store FP16 inputs. C and D use FP32 for the accumulated values. The arrow describes numeric types; it does not change the matrix dimensions.

Matrix dimensions are not thread counts.

A cooperating group of GPU threads carries out the operation. An 8×16×16 shape does not mean 8 threads, 16 threads or 2,048 threads.

These equations explain the mathematical operation. Floating-point rounding depends on the arithmetic and implementation; tile shape alone does not establish accuracy or speed.

02

The fixed-shape landscape

Each filled cell means at least one supported arithmetic combination uses that geometry. All fixed entries here have subgroup scope.

Intel uses an 8×16 output tile. FP16 and BF16 use K=16; integer inputs use K=32. B70 and B580 return the same six typed entries.

Radeon uses a 16×16 output tile. The 780M, RX 7900 XTX and RX 7600 all expose only 16×16×16, with multiple signedness, accumulator and saturation combinations. The Xclipse (M51) exposes the same single shape.

Adreno 840 always uses M = 64. N can be 16, 32 or 64; FP16 uses K=16 with FP16 accumulation only (no FP16 → FP32), integer inputs use K=32 and FP32 uses K=8.

Mali-G1 has the smallest tiles. 4×8×8 and 16×32×32 for FP16, 4×16×16 for INT8, plus FP32 4×4×4 and 16×16×16.

Is the matrix path really accelerated?

A listed shape only promises a correct result; a driver may lower it to ordinary FMA. The ratio divides the measured register-resident matrix roof by the scalar roof of the same input type (fp16 FMA, int8 dot) from confirmed short-run roofline campaigns. ISA or hardware-counter evidence outranks the ratio. The Xclipse (M51) has real matrix hardware per its owner; its fp16 ratio of 1.0× is unexplained. 05

NVIDIA: a family of flexible tiles

The queried RTX 4070 Ti SUPER and Orin Nano also expose flexible dimensions and workgroup scope through VK_NV_cooperative_matrix2.

(M, N, K) = (a·gM, b·gN, c·gK)
a, b and c are independent positive integers; each resulting dimension must be ≤ 1024.
Table 2. Flexible-dimension granularities, not an exhaustive fixed-shape list.
ScopeWorkgroup invocationsFP16 / BF16 granularityINT8 / UINT8 / FP8 granularity
SubgroupNot specified16×16×1616×16×32
Workgroup32 or 6416×16×1616×16×32
Workgroup12832×16×1632×16×32
Workgroup25632×32×1632×32×32

Example: subgroup FP16 supports a 32×64×16 API tile because all three dimensions are multiples of 16. A 24×64×16 tile fails the M granularity rule.

At every row: FP16 → FP16/FP32, BF16 → FP32, INT8 → INT32 and UINT8 → UINT32. FP8 E4M3/E5M2 → FP16/FP32 is RTX-only and uses the integer column's granularity. All flexible entries are non-saturating. Shader resource limits still apply; satisfying these dimension rules does not guarantee a particular shader will compile or execute. Intel advertises the NV2 extension but returns both flexible-dimension and workgroup-scope features as false.

06

Evidence, scope & reproducibility

What was measured

A capability probe enumerated Vulkan physical devices, matched registered UUIDs, and queried KHR/NV matrix properties, NV flexible dimensions and feature flags. No matrix shaders were dispatched; these are driver-advertised capabilities, not execution validation or benchmark results.

What “WMMA” means here

WMMA is used as shorthand for Vulkan cooperative matrices. This report does not enumerate CUDA WMMA, AMD native WMMA or Intel DPAS instruction shapes. Features must be enabled by applications, and support may change with the installed driver.

Devices outside this atlas

The gpu-lab snapshot also queried the Ryzen 9600X iGPU, Galaxy S24+ Xclipse 940 and Pixel 7a Mali-G710 MP7: none exposed a cooperative-matrix extension. Other homelab GPUs were not queried in this snapshot; their omission does not establish a lack of hardware matrix support.
